# SoundFace 安装与分发模型

定位基线及官方资料核对日期：2026-10-15。本文描述计划采用的分发方式与待验证风险，当前仓库没有可安装产物。

## 分发决策

首版以官网提供的签名、公证 pkg 为主要入口，交付 SoundFace 桌面应用、CoreMediaIO Camera Extension 和 AudioServerPlugIn 虚拟麦。App Store 作为单独评估项，不是首版发布依赖。

一个 pkg 可以承载多个组件，但摄像头扩展和 HAL 插件仍遵循各自的安装、启用、升级与卸载机制。安装包运行成功不等于两个虚拟设备都已可用。

## 摄像头扩展与 HAL 虚拟麦的差异

| 项目 | CoreMediaIO Camera Extension | AudioServerPlugIn 虚拟麦 |
| --- | --- | --- |
| 系统模型 | 由系统管理的摄像头系统扩展 | Core Audio 音频服务器加载的 HAL 插件 |
| 打包位置 | 随宿主 `.app` 打包，扩展位于应用包内 | 独立 `.driver`，安装到 `/Library/Audio/Plug-Ins/HAL` |
| 安装与启用 | 宿主进入 `/Applications` 后发起系统扩展激活请求，用户按系统流程允许 | pkg 通过系统安装器以管理员授权写入系统级插件目录，再验证音频服务加载 |
| 权限区别 | 扩展启用与物理摄像头采集权限分开管理 | 管理员安装授权与物理麦克风采集权限分开管理 |
| 生效条件 | 系统接受激活并允许使用；可能存在等待授权或等待重启状态 | 必须确认音频服务已加载插件；不能承诺安装即热加载 |
| 更新方式 | 更新宿主内的扩展，经系统请求处理替换与版本状态 | 安装器更新插件，处理运行中使用、版本配套和重新加载 |
| 卸载方式 | 通过系统扩展生命周期发起停用并确认结果 | 经授权移除本产品的 HAL 插件，并处理重新加载或重启 |
| App Store 判断 | Apple 明确支持摄像头扩展随应用通过 App Store 分发 | 系统目录安装与管理员授权不符合普通商店应用的自包含安装模式，须单独评估 |

摄像头扩展的打包、激活目录与系统提示见 [Apple Camera Extension 创建指南](https://developer.apple.com/documentation/coremediaio/creating-a-camera-extension-with-core-media-i-o)；系统扩展的签名要求见 [System Extensions](https://developer.apple.com/documentation/systemextensions)。HAL 位置和重启要求来自 [Apple AudioServerPlugIn 示例](https://developer.apple.com/documentation/coreaudio/creating-an-audio-server-driver-plug-in)。表中的 SoundFace 安装器和恢复流程属于产品设计，尚待实际验证。

## 官网 pkg 安装流程

1. 安装前说明包含应用、摄像头扩展和虚拟麦组件，检查目标系统、已有版本与正在进行的音视频会话。
2. 用户通过 macOS 安装器授权安装应用和 HAL 插件。应用内不收集管理员密码，也不以普通 UI 进程直接写系统插件目录。
3. 首次启动分别展示“应用已安装”“摄像头扩展状态”“虚拟麦加载状态”；宿主发起摄像头扩展激活，按系统返回值引导用户操作。
4. 用户首次使用对应输入时，分别请求物理麦克风和摄像头权限。只使用音频时不要求开启摄像头。
5. 检测虚拟设备枚举和实际输出；若音频插件尚未生效，提示保存工作并按已验证流程重启。Apple 的 HAL 示例要求重启，因此首版不能承诺免重启安装。
6. 引导用户在目标应用中选择 SoundFace 虚拟麦或虚拟摄像头；提供试听、预览与故障提示，设备出现在列表中仍不等于已成功接收媒体。

不在后台无提示地重启系统音频服务，以免打断其他应用的会议、录制和播放。具体 macOS 设置入口可能随版本变化，应根据系统状态提供引导。

## 签名、公证与发布

- 官网应用、原生二进制、插件和扩展按各自代码签名要求处理；安装包使用对应的 Developer ID Installer 签名。SoundFace 采用宿主与摄像头扩展相同团队签名，并验证嵌套组件与 entitlement 配置。[System Extensions](https://developer.apple.com/documentation/systemextensions)
- 对最终分发产物执行 Apple 公证，按支持的格式附加公证票据，并在干净机器上验证 Gatekeeper、安装、扩展激活和 HAL 加载。公证不能代替功能测试或 App Store 审核。[Apple 公证指南](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution)
- 维护应用、引擎、扩展和 HAL 插件的版本兼容关系；升级前检测使用状态，失败后保留可诊断信息和恢复路径。
- 发布说明列出已验证的系统、芯片及目标应用版本，以及是否需要重启。不要求用户关闭 SIP 或长期降低系统安全设置来使用正式版。

## App Store 单独评估

Camera Extension 可随应用进入 App Store，不等于包含 HAL 虚拟麦的完整 SoundFace 自动满足商店要求。Apple 的 Mac App Store 规则 2.4.5 要求沙盒、自包含安装，并限制第三方安装器、管理员提权及应用包外资源安装。[App Review Guidelines 2.4.5](https://developer.apple.com/app-store/review/guidelines/#hardware-compatibility)

据此，当前采用“App Store 另评”的产品判断，不承诺完整版本可直接上架，也不把某个技术组件概括为永久禁止。评估需覆盖 Electron 与原生组件的沙盒权限、虚拟麦交付可行性、商店版功能边界及当时的审核规则。不得预设引导用户另装官网 HAL pkg 就能满足商店审核；若需要不同产品形态，应另作决策并明确告知功能差异。

## 风险与验证要求

| 风险 | 对用户的影响 | 发布前验证与处理 |
| --- | --- | --- |
| 摄像头扩展等待允许或被设备管理策略限制 | 应用能打开但虚拟摄像头不可用 | 显示系统实际状态；测试允许、拒绝、重新激活与受管理设备限制 |
| HAL 插件未加载或系统更新后失效 | 虚拟麦缺失、无声或不可选 | 验证签名、目录权限、架构与系统版本；准备重启及重装指引 |
| HAL 插件异常影响音频服务 | 可能干扰其他应用音频 | 插件保持最小职责；验证崩溃、欠载和引擎断连，提供恢复与卸载方式 |
| 组件版本不一致或更新被打断 | 音视频单侧可用、状态异常 | 校验组件版本；验证升级失败、重复安装及兼容版本恢复 |
| 第三方应用缓存设备或限制虚拟输入 | 系统中可见，应用中不可用 | 建立应用/版本矩阵；必要时提示重新打开目标应用，不声称全兼容 |
| 签名、公证或安装包内容出错 | 下载后被阻止运行或安装 | 在干净系统验证最终产物，包括联网及已附票据后的离线验证 |
| 直接删除应用留下系统组件 | 虚拟麦残留、设备状态混乱 | 提供完整卸载入口与书面恢复说明，逐组件确认清理结果 |

## 升级与卸载原则

升级前告知用户结束正在进行的会议、直播或录制，停止输出并检查组件占用。摄像头扩展通过系统更新机制处理；HAL 插件通过安装器替换，按验证结果提示重新加载或重启。不承诺正在被系统加载的旧组件可以立即热替换或热回滚。

完整卸载应先停止采集和输出，发起摄像头扩展停用请求并跟踪完成状态，再经授权移除 SoundFace 自己的 HAL 插件，最后清理应用与用户选择删除的配置。系统若要求重启或延后完成，应明确显示待完成事项。禁止把“拖入废纸篓”描述成完整卸载，也不能删除其他厂商的 HAL 插件。

发布前需验证全新安装、重复安装、升级、安装中断、权限拒绝、重启后使用、完整卸载和重新安装。支持矩阵与验收结果回填至产品文档后，才可对外承诺安装体验。
