# SoundFace 架构方向

定位基线：2026-10-15。本文是待实现的架构约束，不代表已有代码或验证结果。

## 总体结构

```text
Electron + React 控制界面 / 预览
         │ 控制命令、配置、状态；受控的低频预览
         ▼
原生桥接与会话管理（Swift / Objective-C++）
         │
         ▼
原生实时引擎（Swift / Objective-C++ / C++）
  ├─ 物理麦克风 → 降噪 → 预设变声 → 音频缓冲
  │                                  ↓
  │                         AudioServerPlugIn → 虚拟麦 → 外部应用
  └─ 物理摄像头 → 人物分割 → 背景合成 → 视频帧
                                     ↓
                          Camera Extension → 虚拟摄像头 → 外部应用

原生引擎 ← 可选云端适配层 → 后续重模型服务
```

控制通道与媒体通道分离。UI 下发参数并显示状态；连续音视频数据由原生引擎与系统设备组件交换，不经过 React 状态或 JavaScript 实时回调。图中的处理顺序是初始逻辑方案，具体算法组合在后续效果验证中确定。

## 模块职责

| 模块 | 负责 | 边界 |
| --- | --- | --- |
| Electron + React | 设备选择、预设、开关、安装引导、状态与预览 | 只做控制和预览，不承担实时 DSP、分割推理或虚拟设备实现 |
| Electron 主进程与原生桥接 | 校验控制请求、管理引擎生命周期、汇总状态 | 渲染进程仅通过受限桥接访问能力，不直接操作系统插件或执行特权安装 |
| Swift | macOS API 集成、采集与会话管理、权限和扩展生命周期 | 不把高频音频回调变成 UI 或异步网络任务 |
| Objective-C++ | Apple 媒体对象与 C++ 引擎的互操作 | 明确缓冲区所有权、线程与对象生命周期 |
| C++ | 实时 DSP、缓冲与时钟处理、必要的高性能算法 | 算法和设备输出解耦，避免在实时路径分配内存、阻塞或访问网络 |
| CoreMediaIO Camera Extension | 发布虚拟摄像头、协商格式并向客户端提供帧 | 使用原生扩展；不在扩展中承载 Electron 或重模型服务 |
| AudioServerPlugIn | 发布虚拟音频输入设备，向 Core Audio 客户端提供处理后的 PCM | 保持插件精简，不在音频服务上下文中运行 UI、模型下载或云端请求 |
| 可选云端适配层 | 后续重模型请求、超时、取消与降级 | 首版基础链路不以云端可用性为前提 |

原生引擎拟与 UI 分离运行；使用何种桥接、进程启动方式及缓冲传输协议，要在系统链路原型中验证后确定。

## 虚拟摄像头

采用 CoreMediaIO Camera Extension。原生引擎输出合成后的帧，扩展向系统发布设备和流，外部应用通过标准摄像头选择入口使用它。Apple 将 Camera Extension 定义为随宿主应用打包的系统扩展，支持 macOS 12.3 及以上；这是 API 下限，SoundFace 的实际最低系统版本仍需结合 Electron 与原生依赖验证。[Apple 创建指南](https://developer.apple.com/documentation/coremediaio/creating-a-camera-extension-with-core-media-i-o)

宿主负责激活请求、用户授权提示与状态反馈。摄像头采集权限和扩展启用是不同状态，不能以其中一个成功推断另一个成功。安装生命周期统一见 [INSTALL_MODEL.md](INSTALL_MODEL.md)。

## 虚拟麦克风

采用 Core Audio AudioServerPlugIn，在系统中发布供其他应用选择的音频输入设备。原生引擎读取物理麦克风并完成降噪、变声后，把 PCM 送入受控缓冲，由插件按设备时钟提供给客户端。

该组件属于 HAL 音频服务器插件，与 Camera Extension 的激活机制不同。Apple 的示例将 `.driver` 安装到 `/Library/Audio/Plug-Ins/HAL`，并要求重启以加载示例。[Apple 音频服务器插件示例](https://developer.apple.com/documentation/coreaudio/creating-an-audio-server-driver-plug-in)

首版以官网 pkg 安装此组件为主。不能假设 Electron 安装后自然获得虚拟麦，也不能将 HAL 插件按摄像头扩展的流程启用。App Store 方案另行评估。

## 实时媒体通道与故障边界

- 音频拟使用有界环形缓冲，视频评估共享表面或其他低拷贝机制；具体 IPC 需验证插件宿主沙盒、访问控制和生命周期，不能直接假定任意进程均能共享内存。
- 控制命令与连续媒体帧采用不同通道；预览取降频或缩小后的副本，不阻塞主输出链路。
- 使用明确的时间戳、采样率和帧率；音频重采样、视频背压与音画漂移修正归原生引擎负责。
- UI 关闭窗口不应意外中断正在使用的输出；显式退出或停止输出则释放输入，并通知设备组件进入安全空闲状态。具体后台生命周期在原型阶段确定。
- 引擎失联或缓冲欠载时，虚拟麦输出静音，虚拟摄像头输出明确的占位画面；不自动切回未经处理的原声或真实背景。用户主动关闭效果属于独立操作。
- 多客户端同时打开、设备拔插、睡眠唤醒和权限撤销必须纳入验证；对不支持的组合提供明确状态。

## 轻本地、重云端

| 本地基础能力 | 后续可选云端能力 |
| --- | --- |
| 输入采集、轻量降噪、预设变声、人物分割与静态背景合成 | 计算密集型声音模型或生成式音视频处理 |
| 时钟、缓冲、音画同步、虚拟设备与基础预览 | 重模型推理及必要的任务管理 |
| 离线可用的基础预设和安全降级 | 依据网络、成本与用户选择启用的增强效果 |

“轻本地”要求控制本机负载，不代表把每一帧都上传云端；“重云端”是后续重模型的部署方向，不把零样本克隆、同传或数字人提前纳入首版。

默认不上传原始音视频。未来启用云端能力时须明确上传范围、数据保留方式及费用；设置超时和取消，不允许网络等待阻塞设备回调。云端不可用时退回已告知用户的本地预设，或进入静音/占位状态；不得悄悄输出原始输入。

## 分发与待验证事项

官网签名、公证的 pkg 为主要分发入口，包含桌面应用、随应用打包的摄像头扩展和 HAL 虚拟麦组件。pkg 统一交付入口，不统一两个设备组件的系统安装机制。App Store 的沙盒、功能范围和审核可行性另评。

进入实现前的验证项：系统与芯片支持矩阵、Electron 宿主与扩展签名打包、原生桥接、媒体 IPC、采样格式、目标应用兼容性、端到端时延、持续资源占用、升级与卸载恢复。当前不锁定尚未测量的性能数字，也不声明全软件兼容。
